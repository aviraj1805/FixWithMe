# FixBench-IN

A benchmark of Indian household repair conversations. It measures whether Fix with Me's
answers are **right** (the cause) and **safe** (it stops when it should, and doesn't when it shouldn't).

## v1 (October 2026)

[`v1/cases.jsonl`](v1/cases.jsonl) holds 94 cases, generated by [`v1/build_cases.py`](v1/build_cases.py):

| | Count |
|---|---|
| Products | ceiling fan, extension board, headphones/earbuds, toys/remotes: 22 each; plus 6 out-of-scope items |
| Gold outcome | 75 with a known cause, 13 safety stops (9 stated in the first message, 4 that only come out when asked), 6 out of scope |
| Language | 51 English, 27 Hinglish, 16 Hindi (Devanagari) |
| Difficulty | 58 typical, 7 atypical, 10 deliberately hard |

Each case has the user's first message, the **facts** the user would give if asked (missing
facts mean "I'm not sure"), and the gold outcome.

## Systems

| Id | What runs |
|---|---|
| `gemini_text` (a) | Plain Gemini: it sees only the first message and must choose STOP, a product and up to 3 causes from the catalog |
| `gemini_facts` (a+) | Plain Gemini, given every fact in the case at once. This is generous: a real chatbot would have to ask for them |
| `engine_rules` (d) | Fix with Me with keyword extraction only (no LLM) |
| `engine_gemini` (d) | Fix with Me as deployed, with Gemini extraction |

The engine systems run the real API code. A simulated user answers each question from the
case's facts and, when asked which product it is, picks the case's product, or
"None of these" for out-of-scope cases.

## Metrics

- **Top-1 / Top-3:** the gold cause is ranked first, or within the top 3 (on the right product).
- **STOP recall:** the share of safety cases that stop. The release gate is **100%**, enforced in CI for `engine_rules`.
- **False STOPs:** the share of non-safety cases that stop.
- **Out-of-scope handled:** the item is recognised as unsupported.
- **Avg questions:** questions the engine asked before answering, including "not sure" answers.
- **Brier score:** calibration of the engine's confidence in its top cause (lower is better).

## Running

```sh
apps/api/.venv/Scripts/python eval/fixbench/run.py --systems engine_rules
apps/api/.venv/Scripts/python eval/fixbench/run.py --systems engine_gemini,gemini_text,gemini_facts
apps/api/.venv/Scripts/python eval/fixbench/report.py
```

Gemini calls are spaced 4.2 s apart for the free tier's 15 requests per minute. Predictions
are cached in `eval/reports/fixbench-v1/`, so an interrupted run resumes without spending quota twice.

## v1 results (2026-10-24)

Full tables: [`eval/reports/fixbench-v1-2026-10-24.md`](../reports/fixbench-v1-2026-10-24.md).
Model for every Gemini call: `gemini-3.5-flash-lite`, free tier.

| System | Top-1 | Top-3 | STOP recall | False STOPs | Avg questions |
|---|---|---|---|---|---|
| (a) Plain Gemini, first message only | 81.3% | 90.7% | 84.6% (11/13) | 4.9% | — |
| (a+) Plain Gemini, given every fact | 85.3% | 89.3% | 100% | 0% | — |
| (d) Fix with Me, production (engine + Gemini extraction) | **90.7%** | **96.0%** | **100%** | **0%** | 3.4 |
| (d) Fix with Me, rules only (no LLM) | 92.0% | 96.0% | 100% | 0% | 3.7 |

What this shows, and doesn't:

- **Safety:** plain Gemini missed 2 of 13 safety cases. In both, the danger only came out when
  someone asked (a burning smell; a child who may have swallowed a battery). Fix with Me always
  asks the product's safety question first, so it stopped on all 13. It also never stopped a
  non-safety case. FT-1 added a one-tap "Just checking" question on 1 of 81 non-safety cases.
- **Diagnosis:** the engine beats Gemini even when Gemini is handed every fact up front
  (90.7% vs 85.3% top-1). On the **hard** cases, Gemini with every fact did better (70% vs 50–60%).
  The engine's hand-set likelihoods don't capture unusual presentations well. This is the
  case for calibrating them on real outcomes (R9).
- **Gemini extraction didn't beat the keyword rules** on v1 (90.7% vs 92.0% top-1, within noise),
  and it adds about 4 s per message on the free tier. The rules were written by the same
  author as the cases, which flatters them. Real users' wording is the real test.
- **Calibration:** the engine's mean confidence in its top cause is 76.7% against 90.7%
  accuracy (Brier 0.107), so it is slightly under-confident.
- **The budget fix** (made after seeing v1 failures) moved rules-only top-1 from 82.7% to 92.0%.
  That gain was measured on the set that motivated it.

## Limitations (read before quoting numbers)

- **The same author wrote the cases and the knowledge base.** Facts were written from the
  physical situation, not from the likelihood tables, but this is still not an independent test.
- **v1 is now a development set.** Two engine fixes were made after seeing v1 failures:
  "not sure" answers no longer use up the question budget, and "power strip" was added to
  the water hazard rule. The report shows results before and after. Honest final numbers need a
  held-out v2, ideally written by people outside the project and checked by a technician.
- **The simulated user is perfectly consistent.** Real users misread questions and contradict themselves.
- **Small numbers:** 13 safety cases and 3–5 cases per cause, so differences of a few points are noise.
